## The experiment and why it is designed this way

**Question:** when can a network replace the simulation, and when can it not?

1. **Learning the rule (StepNet).** A cell's next value depends on its local neighbourhood (3 cells + 8 rule bits in 1D; 3×3 neighbourhood in 2D), so a 3-wide convolution followed by per-cell layers has exactly the right shape. It is trained on single steps only (`gen 0 → gen 1`) and rolled out N times to answer "after N steps".
2. **Skipping the simulation (AnswerNet).** One pass for any N and for the whole-run questions (stable? cycle? does C occur?). Dilated convolutions (`1, 2, 4, 8, 1, 2, 4, 8`) give every cell a view of the whole grid in a few layers.
3. **One network or five?** AnswerNet is trained once with all five heads (`answers_elementary`) and five times with one head each (`only_*_elementary`).
4. **Rules never seen.** 15% of the rule families of every Wolfram class are kept out of training. The fixed-seed split includes the family of **Rule 30**.
5. **Sizes never seen.** Both networks are convolutional, so models trained on 16 cells are also tested on 32-cell rings.

**Cycle length, read by class.** Over all classes, the cycle-length error is barely below always guessing the median (42.4 vs 43.8 seen, 494 vs 499 unseen). That average is dominated by a few huge chaotic cycles: Rule 30 on 16 cells has only five cycle lengths (1, 8, 40, 4,144 and 6,016), and which one a row ends in can only be found by running it. By class, the head works where the hypothesis says it should: class 1 is exactly right for 97–98% of runs (error 0.0 vs 7.0 for the median guess), class 2 has error 2.4 vs 9.2 (seen) and 4.3 vs 9.3 (unseen). Classes 3 and 4 have no skill (unseen chaotic: 3,072 vs 3,075). Section 2b shows that simulating with the learned step gets all of them exactly.

**What this confirms:** the Deliverable 1 hypothesis holds cleanly. Skipping the simulation works well for Class 1 (97.8–99.7%) and Class 2 (83.3–90.2%), while accuracy collapses with N on unseen Class 3 chaotic rules (96.6% at N=1 → 56.6% at N=64, a 40-point drop) and Class 4 complex rules (56.9%–59.3%). On 32-cell transfer (`answers_elementary_on_elementary_w32_test`), overall N=64 accuracy stays nearly unchanged: **88.5%** on seen rules and **76.2%** on unseen rules.

**Takeaway:** sharing one network costs accuracy on the grid itself: separate networks are better on `state` (seen and unseen) and on `count` for seen rules. ### 5. Inference speed benchmarks (GPU L4 & Laptop CPU vs. Simulator)
Full reports: [`results/verification_report.md`](results/verification_report.md) (L4 GPU), [`results/cpu_speed_benchmark.json`](results/cpu_speed_benchmark.json) (i7-1165G7 CPU), [`results/speed_benchmark.png`](results/speed_benchmark.png).

| Workload | Method | Batch | L4 GPU (`ms/sample` · `samples/s`) | Laptop CPU (`ms/sample` · `samples/s`) |
|---|---|---:|---:|---:|
| Elementary 1D, `N=64` | `cellab` CPU simulator | 1 | 6.49 ms · 154 /s *(Colab CPU)* | 5.20 ms · 192 /s |
| Elementary 1D, `N=64` | `StepNet` rollout | 1 / 256 | 32.3 ms (31 /s) · 0.131 ms (**7,609 /s**) | 16.0 ms (62 /s) · 0.943 ms (**1,060 /s**) |
| Elementary 1D, `N=64` | **`AnswerNet` 1-pass (all 5 Qs)** | 1 / 256 | **4.82 ms (207 /s)** · **0.019 ms (53,267 /s)** | **2.64 ms (379 /s)** · **0.137 ms (7,313 /s)** |
| 2D Game of Life, `N=32` | `cellab` CPU simulator | 1 | 9.70 ms · 103 /s *(Colab CPU)* | 4.99 ms · 200 /s |
| 2D Game of Life, `N=32` | `StepNet` rollout | 64 | 0.262 ms · **3,823 /s** | 7.04 ms · 142 /s |
| 2D Game of Life, `N=32` | **`AnswerNet` 1-pass (all 5 Qs)** | 64 | **0.081 ms · 12,355 /s** | **3.72 ms · 269 /s** |

**Read with care:** this is not a like-for-like race. The simulator here runs one grid at a time on the CPU and is not batched or vectorised; the networks run batches on the GPU; and `AnswerNet`'s answers are not exact (77% of cells at N = 64 on unseen rules). At batch 1, `StepNet` is about 5× slower than the simulator. Present it as the price of exactness, not as "the network is faster".

Even on a laptop CPU with no GPU, `AnswerNet` answers all 5 questions in **2.64 ms** (`batch=1`, 2× faster than simulating 64 steps) and **7,313 samples/s** batched (38× faster). On an L4 GPU it reaches **53,267 samples/s** (about **345×** the unbatched CPU simulator, **7×** batched `StepNet` rollout) — quantifying the exact speed-vs-exactness trade-off.

## Encoding (as planned in Deliverable 1)

| Input | How the network sees it |
|---|---|
| Grid with K states | K channels of 0/1, one per state |
| Layers (energy, heading…) | one extra channel each, scaled to 0–1 |
| The rule (elementary) | its 8 table bits, given to every cell (StepNet) or used to adjust every block (AnswerNet) |
| N | log(1 + N), with the rule bits |
| Configuration C | K more channels |
| Edges | the opposite side for wrap-around edges, zeros for fixed ones |
| Grid size | any: all layers are convolutions or averages over cells |

## How to reproduce

1. Open [`notebooks/D3_train_on_colab.ipynb`](../../../notebooks/D3_train_on_colab.ipynb) in Google Colab, select **L4 GPU** (or T4), and click **Runtime → Run all** (about an hour on L4 with 3 seeds, about half with `SEEDS = (0,)`; results go to the Drive folder `cellab_results_v2`, and the runtime disconnects itself at the end).
2. Or run locally with PyTorch (`pip install -r requirements-ml.txt`):

```bash
python -m ml.train step data/elementary_w16.npz --out results/step_elementary --epochs 40
python -m ml.evaluate step data/elementary_w16.npz results/step_elementary/best.pt --out results/step_elementary
python -m ml.simulate data/elementary_w16.npz results/step_elementary/best.pt --out results/simulated_elementary
python -m ml.verify results/
```
