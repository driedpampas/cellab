State space and storage

Size of the state space and how we store states

2⁶⁴ ≈ 1.8 × 10¹⁹

possible rows of a 64-cell elementary automaton

3²⁵⁰⁰ ≈ 10¹¹⁹²

possible states of a 50 × 50 grid with 3 cell types

Because of this, we only keep fingerprints of the states a run actually visits.

How we store

  • Grids as NumPy arrays: 1 byte per cell
  • 2-state grids bit-packed: 64 × 64 cells in 512 bytes
  • Long runs: a full snapshot every k steps, only changed cells in between
  • An experiment = spec + parameters + seed, so any run can be replayed exactly
  • Storing every generation is optional, as the brief asks

This answers the "shape of the space, possible values, efficient storage" part of the brief and our notes. The state space is astronomically large, so anything that enumerates states is out; we only ever touch the states a run visits. Saving the spec, the parameters and the random seed is enough to reproduce a run, so storing generations is a convenience, not a necessity.
