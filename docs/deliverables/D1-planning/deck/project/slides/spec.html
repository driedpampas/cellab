Describing an automaton as a spec file

{
  "name": "Brian's Brain",
  "states": ["OFF", "FIRING", "DYING"],
  "neighbourhood": "moore",
  "edges": "wrap",
  "rules": [
    {"from": "FIRING", "to": "DYING"},
    {"from": "DYING", "to": "OFF"},
    {"from": "OFF", "to": "FIRING",
     "if": "count(FIRING) == 2"}
  ],
  "otherwise": "unchanged"
}

The engine reads the rules from the file

It only works with states, neighbours, counts and conditions, so the same code runs every automaton.

Variants need only small edits

For example, requiring 3 firing neighbours means changing 2 to 3.

This is how we avoid hard-coding 15 simulations. Each automaton is a data file; the engine is a general interpreter. "moore" means all 8 surrounding cells. The format shown is a draft. Designing it so all 15 examples fit, including movement and agents, is the main task of Deliverable 2.
