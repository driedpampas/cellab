Reopening a run exactly where it stopped

@classmethod
def open(cls, path: str | Path) -> "Run":
    folder = RunFolder(path)
    if not folder.file(RunFolder.EXPERIMENT).is_file():
        raise StorageError(f"{folder.path} is not a run folder (no {RunFolder.EXPERIMENT})")
    experiment = load_experiment(folder.file(RunFolder.EXPERIMENT))  # the folder's own copies
    saved = folder.load_checkpoint()
    if experiment.automaton.digest != saved["automaton_digest"]:
        raise StorageError(...)  # automaton.json was edited: refuse
    count = saved["step"] + 1  # steps 0..step are saved
    history = History.rebuild(folder.read_fingerprints(count))
    folder.truncate(RunFolder.FINGERPRINTS, FINGERPRINT_SIZE, count)
    if experiment.store_generations:
        folder.truncate(RunFolder.GENERATIONS, saved["grid"].nbytes, count)
    state = RunState(step=saved["step"], grid=saved["grid"], initial=saved["initial"], seed=saved["seed"],
                     rng=restore_generator(saved["rng_state"]), history=history, captured=saved["captured"])
    return cls(experiment, folder, state)

Ctrl+C never cuts a step in half

The handler only sets a flag; the loop stops between steps, after a checkpoint.

Crash between checkpoints

Extra steps in the .bin files are cut back, then recomputed identically.

Two of the grey comments were added for this slide, and the long refusal message is shortened to "..."; everything else is the real code. After open, the same advance loop continues as if nothing happened. That is why a stopped-and-resumed run equals an uninterrupted one, byte for byte. The Ctrl+C handler is installed only while a run is advancing and the previous handler is restored afterwards.
