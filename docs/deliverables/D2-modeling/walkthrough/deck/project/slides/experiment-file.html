An experiment file says what to do with it

{
  "name": "Forest fire, grid from the brief",
  "automaton": "../automata/forest_fire.json",
  "initial": {
    "type": "text",
    "rows": ["TTTT.", "TT.TT", ".TFTT", "TTTTT"],
    "legend": {"T": "TREE", "F": "FIRE", ".": "EMPTY"}
  },
  "steps": 8,
  "max_steps": 1000,
  "questions": [
    {"ask": "state_after", "n": 2},
    {"ask": "stable"},
    {"ask": "occurs", "rows": ["T....", ...]},
    {"ask": "count_after", "n": 3, "value": "TREE"},
    {"ask": "cycle"}
  ]
}

automaton: which file to run. One automaton, many experiments.

initial: generation 0, drawn as text (or “random”, or “single”).

steps: generations to simulate and store.

max_steps: how far the run may go to answer questions.

questions: the brief’s five, with their parameters (n, value, rows).

Not shown: seed, store_generations, checkpoint_every, parameters.

This file is the "experiment parameters" part of the deliverable, including the parameters of the five questions. Without a seed, the run picks one and writes it into its run folder, so the run can always be repeated. "parameters" can override the automaton's own parameters, e.g. which elementary rule to run.
