A test that proves the code knows no automaton

def test_no_state_name_from_any_example_appears_in_the_code():
    names = state_names()  # every state name in automata/*.json (3+ letters)
    assert len(names) > 10  # the check is not vacuous
    for path in (ROOT / "src" / "cellab").glob("*.py"):
        code = path.read_text(encoding="utf-8")
        found = sorted(name for name in names if re.search(rf"\b{re.escape(name)}\b", code))
        assert not found, f"{path.name} mentions {found}"

It caught a real slip

The first time it ran, it failed: an example in a docstring in grids.py said “TREE”. Harmless, but exactly the kind of leak it exists to catch. Fixed with neutral names (STATE_X).

What it checks

EMPTY, TREE, FIRE, OFF, FIRING, DYING, CRYSTAL, CAR, DEAD, ALIVE, SUSCEPTIBLE… none may appear anywhere in src/cellab, not even in comments.

The professor's note said nothing in the code should be specific to one automaton. This test makes that mechanical: it collects every state name used by our example files and fails if any of them appears in the engine's source code. The grey comment on the second line was added for the slide. A second test in the same file runs every example experiment, so every automaton is exercised on each test run.
