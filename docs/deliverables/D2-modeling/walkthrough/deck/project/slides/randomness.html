Same seed, same result (max score) · randomness.py · real output

Two runs with seed 42 are identical; seed 43 is not

One generator per run

PCG64(seed). Nothing else makes random numbers: a test scans the code.

A fixed order of draws

Initial world first, then one grid per random() per step, in rule order.

Saved with the run

The seed goes into the run folder; the generator’s state into every checkpoint.

Why the order matters: if the number of random draws per step depended on the data (for example, "and" stopping early when its first part is False), two runs could drift apart. Our "and"/"or" always evaluate every part, and every rule is evaluated for every cell every step, so the draws are always the same. If an experiment has no seed, new_seed() picks one and the run folder records it, so even "random" runs can be repeated exactly.
