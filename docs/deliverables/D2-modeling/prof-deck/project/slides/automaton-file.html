World state and rules

Each automaton is described in a JSON file

{
  "name": "Forest fire",
  "dimensions": 2,
  "states": ["EMPTY", "TREE", "FIRE"],
  "neighbourhood": "von_neumann",
  "edges": {"type": "fixed", "value": "EMPTY"},
  "rules": [
    {"when": "self == FIRE", "then": "EMPTY"},
    {"when": "self == TREE and count(FIRE) >= 1",
     "then": "FIRE"}
  ]
}

Rules are small expressions, checked against a whitelist when the file is loaded.

They cover named states, numbers (sandpile), probabilities (random fire) and pattern tables (Rule 30).

A new automaton is a new file. The engine is never changed.

CelLab · Deliverable 2 · automata/forest_fire.json

The rule text is parsed with Python's own parser and checked node by node, so a file can never run arbitrary code: a rule that tries to call a system command is rejected. Typos get suggestions, e.g. "unknown name 'FIER' (did you mean 'FIRE'?)". Validating a file is a constraint check: states, rules, edges and grids must all be consistent.
