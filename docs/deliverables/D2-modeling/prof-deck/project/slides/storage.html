State storage and recovery

Saving the state and resuming a run

Each run gets a folder

automaton.json
experiment.json
checkpoint.npz
fingerprints.bin
generations.bin
answers.json

Ctrl+C, a crash or --stop-at: cellab resume continues from the last checkpoint.

CelLab · Deliverable 2 · the checkpoint holds the grid, step, seed and random generator state

Checkpoints are written atomically (to a temporary file, then renamed), so a crash never leaves a broken one. Generations and fingerprints are appended to fixed-size record files, so any step can be read back directly, and resuming simply cuts them back to the checkpoint. Resume refuses to continue if the automaton file in the folder was edited.
